# 结核病患者管理 · 本地模拟环境

当前管理端完全使用本地 Mock 数据。默认命令不启动 `backend/` 中的 PHP 服务，不连接原数据库、Redis、OSS、AI 或微信服务。

## 启动

需要 Node.js 22 或以上、pnpm 8.8 或以上。在项目根目录执行：

```bash
pnpm install:all
pnpm dev
```

打开 http://127.0.0.1:3006 。演示账号 `admin`，密码 `Mock123456`，验证码 `1234`。

- 前端：`127.0.0.1:3006`；Mock：`127.0.0.1:3010`。
- 浏览器业务请求统一经过 `/api`，开发及构建预览只转发到本地 Mock。接口不存在直接报错，服务不可用时不会切换原后台。
- `Ctrl+C` 停止本次启动的两个服务。端口占用会明确报错，不自动选择另一个端口或结束其他项目。
- 页面刷新保留本次修改；重启服务恢复初始数据，并清空上传文件及登录会话，需要重新登录。
- 模拟数据以服务启动时的上海日期为基准；持续跨日演示时重启即可重新生成。

## 构建与检查

```bash
pnpm check        # Mock 接口测试、构建、TypeScript 检查
pnpm build        # 生成 frontend/dist；先由 Vite 生成自动导入类型，再执行类型检查
pnpm preview      # 同时启动构建预览与 Mock，地址仍为 127.0.0.1:3006
pnpm mock:check   # 仅接口测试，使用独立随机端口及固定测试时间
```

构建预览前先停止开发服务。`frontend/` 内的 `dev`、`build`、`serve` 也默认采用 `mock` 模式，但单独启动前端时需另行启动 `mock-api`。推荐使用根目录命令，统一管理进程。

保留原生产配置及 GitLab CI 供查阅，本次没有部署或修改原后台。不要将当前模拟账号及内存服务作为正式生产后台使用。

## 项目与数据说明

- [项目结构、业务关系、页面与接口映射](docs/PROJECT.md)
- `frontend/`：现有 Vue 管理端及组件；只修复本次运行所需的配置、公共入口和类型问题。
- `mock-api/`：Node HTTP 服务、关联模拟数据、接口测试；不会执行 PHP 或种子 SQL。
- `backend/`：原服务源码，作为接口契约与业务逻辑参考，不参与本地运行。

覆盖医生端业务菜单、研究与分组、通用方案、提醒方案、患者执行与工作台。患者、个体用药、服药记录、任务、答卷、每日反馈、报告、不良反应和统计共用同一份本地数据；导出为真实 Excel 文件，上传资料保存在 Mock 内存并通过同源地址访问。

管理端支持研究、分组、用药方案、问卷、任务模板、提醒方案、患者连续建档、个体用药和发药，并可跟进用药、任务、反馈、报告及不良反应。`#/patient-app` 提供患者端移动页面，含后台手机号准入、首次双确认、首页/用药/任务/我的四菜单、当天待服药逐项打卡（已完成记录不在患者端展示）、每日反馈、随访问卷、报告上传与核对、不良反应上报、余药估算、提醒偏好、联系信息和健康科普。每日反馈包含体重下降及浏览器语音转文字/文本降级；报告上传有拍摄提示、预览与删除，患者核对保留指标单位、参考范围和可选异常标识；药品卡可展开用药指导。问卷统计已区分答卷份数、参与患者数和题答案行数。
