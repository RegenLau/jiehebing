# 结核病临床研究患者管理后台

这是一个面向结核病临床研究随访场景的后台管理交付项目，包含 Vue 管理后台和独立的 Node.js Mock API。

当前默认开发链路完全使用本地 Mock 数据，不启动 `backend/` 中的 PHP 服务，也不连接生产数据库、Redis、OSS、微信或 AI 服务。患者侧将由真实微信小程序另行实现，本仓库不提供患者端页面、登录或业务接口；Mock 接口不存在时会直接报错，不会回退到原后台。

## 当前状态

- 管理端：研究项目与分组、患者建档、个体用药、发药、服药计划、随访任务、问卷、报告、不良反应、每日反馈、科普内容、药品和账号管理。
- Mock API：所有模块共享同一份内存数据，支持筛选、分页、上传、真实 XLSX 导出和业务回归测试。
- 交付边界：仅交付后台管理页面及其本地 Mock 服务；患者微信小程序不在本仓库实现。
- 当前验证基线：Mock 测试 `46/46` 通过，Vite 构建和 `vue-tsc --noEmit` 通过。

## 技术结构

```text
frontend/    Vue 3 + TypeScript + Vite + Element Plus 管理后台
mock-api/    Node.js 本地 Mock 服务、内存数据和接口测试
backend/     PHP/Webman 原服务源码，仅作为接口和业务参考
docs/        功能架构、业务基线和真实接口交接文档
```

根目录不再提供统一的 `package.json` 或进程托管脚本。前端与 Mock API 需要分别安装、分别启动。

## 本地启动

### 环境要求

- Node.js 22 或以上
- pnpm 8.8 或以上

### 1. 安装依赖

在项目根目录执行：

```bash
pnpm --dir frontend install --frozen-lockfile
pnpm --dir mock-api install --frozen-lockfile
```

### 2. 启动 Mock API

终端一：

```bash
pnpm --dir mock-api start
```

Mock API 监听 `http://127.0.0.1:3010`，健康检查地址为：

```bash
curl http://127.0.0.1:3010/health
```

### 3. 启动前端

终端二：

```bash
pnpm --dir frontend dev
```

访问地址：

- 管理端：<http://127.0.0.1:3006>
- 前端代理健康检查：<http://127.0.0.1:3006/api/health>

两个服务都使用固定端口并启用 `strictPort`。如果端口被占用，服务会明确失败，不会自动切换端口或结束其他进程。停止服务时分别在两个终端按 `Ctrl+C`。

## 构建与测试

由于根目录统一脚本已移除，请直接运行子项目命令：

```bash
# Mock API 全量业务测试
pnpm --dir mock-api test

# Vite 构建并执行 TypeScript 检查
pnpm --dir frontend build
```

构建产物位于 `frontend/dist/`。预览构建结果时先启动 Mock API，再在另一个终端执行：

```bash
pnpm --dir frontend serve
```

预览仍使用 `http://127.0.0.1:3006`，并将 `/api` 转发到 `http://127.0.0.1:3010`。

## 核心业务规则

### 用药方案与分组快照

- 患者入组时保存分组用药、问卷、任务、提醒和取药配置的执行快照。
- 后续修改分组配置只影响之后入组的患者，不覆盖既有患者的安排。
- 个体用药调整生成新版本；已执行记录和旧版本事实永久保留。
- 未来日期的方案先进入待生效状态，当前方案在生效日前继续执行。

### 患者状态与任务

- 患者研究状态包括：`待启用`、`治疗中`、`暂停用药`、`已完成`、`提前退出`、`失访`。
- 当前有效方案开始后自动进入`治疗中`；患者侧身份绑定与授权由真实微信小程序及正式服务端负责。
- 暂停、恢复、退出和失访只影响规则允许的未执行计划，不抹去历史记录。
- 提前退出或失访后，普通未完成任务会取消；明确标记的安全随访仍可保留。
- 取药提醒基于实际发药或余药盘点以及当前个体用法用量动态计算，不把模板数量当作患者已领取药量。

### 问卷、报告与不良反应

- 问卷按任务轮次记录，每轮拥有独立的 `task_id` 和 `answer_id`，同一模板可以多次提交。
- 报告保留原始附件、OCR 原始结果、人工核对结果、补传版本和核对历史。
- Mock OCR 只用于演示结构化流程，不代表真实识别能力或医疗判断。
- 不良反应支持分配负责人、处理状态、联系记录和后续行动；真实安全事件通知渠道与时限仍需按具体研究落实。

### 发药与数据追溯

- 患者建档、首次方案和首次发药按一笔原子操作处理。
- 建档和发药支持 `client_request_id` 幂等键，重复请求不会重复创建业务记录。
- 发药错误通过更正或冲销处理，原记录保留；被冲销数量不再计入余药和取药提醒。
- 工作台指标、列表筛选和导出使用一致的数据口径，导出不受当前分页限制。

## 本地数据行为

- 所有业务数据、会话和上传文件保存在 Mock 进程内存中。
- 页面刷新不会重置数据；重启 Mock 服务会恢复初始数据，并清空本次运行产生的上传和登录会话。
- 模拟日期以 Mock 服务启动时的上海日期为基准；跨日演示时建议重启 Mock。
- 上传文件通过 `/api/mock-files/:id` 在本地访问，允许 JPG、PNG、GIF 和 PDF，单文件最大 10 MB。
- 患者、任务、报告、反馈、用药和不良反应等导出为真实 `.xlsx` 文件。

## 能力边界

当前项目是本地业务原型和接口契约验证环境，不是生产系统：

- 本仓库不包含患者端页面，也不提供 `/app/login`、`/app/logout` 或 `/app/patient/*` Mock 接口。
- 真实微信小程序、可信手机号绑定、订阅消息授权、患者提交接口和发布流程均需在独立患者端项目与正式服务端中实现。
- 未接入真实 OCR、AI 医疗判断、生产数据库、Redis、OSS 或消息渠道。
- `backend/` 中的 PHP 服务未与当前 Mock 演示流程联调。
- 研究角色、项目级权限、盲态访问、安全事件通知责任和生产部署仍需结合具体研究方案验收。
- 示例患者、药品数量、日期、频次和检查结果均不得作为临床处方或医学结论。

接入真实服务端时，应以业务基线文档中的版本、快照、状态、幂等、审核和筛选规则为验收标准，不能只替换接口地址。
