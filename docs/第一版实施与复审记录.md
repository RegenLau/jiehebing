## F01 分组任务逐项提醒时间

### 实现结果

- 移除“随访任务 → 提醒方案”独立菜单及分组详情中的提醒方案页签。
- 分组内每项随访问卷和任务分别设置提醒时间，新增安排默认 `09:00`；不再显示开始、到期、逾期等提醒时机。
- 任务执行日期继续由计时基准、起始偏移、重复间隔和完成期限决定；提醒时间只表达每次安排当天的具体提醒时刻。
- 旧分组缺少逐项时间时，读取接口沿用原提醒快照中的任务时间作为兼容默认值；旧提醒方案接口仅作 Mock 历史兼容，不再进入医生菜单。
- 分组列表显示已设置提醒时间的随访项数量，患者端提醒设置按问卷和任务逐项展示名称及时间。

- 既有患者、项目分组、用药方案、任务、问卷、报告、反馈、导出和登录相关回归全部通过。

## F02 患者连续建档与个体用药调整

- 新增患者改为“基本信息 → 研究分组 → 用药与发药”三个连续步骤；从分组进入时自动带入当前研究、分组、负责人员和日期。
- 主按钮一次保存患者档案、研究归属、个人用药方案和可选的首次发药；任一步校验失败会整体回滚，不留下半完成患者。

## F03 患者手机号准入与首次双确认

### 实现结果

- 在现有 Vue 工程新增 `/patient-app` 全屏移动入口，复用同一构建与本地 Mock，不引入第二套项目。入口无需医生登录，患者会话与医生会话隔离。
- 只有医生后台已建档且允许登录的手机号可以进入；未知手机号返回明确提示且不创建患者。
- 首次进入固定为“基础信息确认 → 当前用药确认”。身份页展示姓名、手机号、性别、出生日期、研究、分组和入组日；药品页逐项展示发药数量、规格、频次、单次用量和服药时点，每种药都确认后才允许最终提交。
- 患者只能确认或报告问题，不能在线改档、改药。“资料有误”和“用药有疑问”均要求填写说明，医生端“状态与核对”页签可查看原始说明和处理状态。
- 用药确认绑定当前治疗方案 ID。医生修改身份关键字段或新增用药方案后，相应确认自动失效，待处理反馈标记为已处理，患者下次进入会看到更新后的内容并重新确认。

### 功能与契约测试

- `pnpm mock:check`：32/32 通过。
- 新增测试覆盖患者令牌隔离、首次步骤顺序、问题说明必填、医生修改后重新确认、旧方案 ID 拒绝提交、当前方案确认后进入完成状态，以及患者操作记录和医生端问题列表。
- 既有医生登录、患者建档、个体用药、发药、计划、任务、报告、反馈、提醒及导出回归全部通过。
- 移动入口相关 Vue、TypeScript 文件 ESLint 和 `vue-tsc --noEmit` 通过；Mock 模块语法和差异空白检查通过。

## F04 检查报告上传、患者核对与医生复核

### 实现结果

- 患者可从报告任务或“我的报告”上传图片/PDF；同一任务只引用一份报告，不重复建记录。
- 上传前显示完整入镜、清晰无遮挡提示；已选图片可预览，PDF有明确文件类型，支持继续添加和删除重选。
- 上传后进入患者核对，可确认报告类型、检查日期以及结构化指标的名称、检测值、单位、参考范围和可选异常标识；医生可再次核对，详情与导出保留同一结果。异常标识仅转录原报告，不触发自动诊断或调药。当前不伪造 OCR 结果，页面明确标注为人工录入过渡。
- 医生端支持核对通过或要求补充；补充原因必填，原始文件、每次补传和核对记录保留。
- 只在报告通过患者核对并进入医生流程后联动相关任务；独立上传不会误完成其他任务。

### 复审结果与边界

- 接口测试已覆盖任务归属、报告补传、原资料保留和任务联动；管理端列表、代录、详情和补充状态已复核。
- 真实 OCR 服务、检查单类型适配和真实样本准确率仍需与外部服务联调，不在本地 Mock 验收结论内。

## F05 每日健康反馈与症状变化

### 实现结果

- 每日反馈支持“无不适”和有症状两个互斥分支，覆盖咳嗽、咳痰、发热、盗汗、乏力、食欲下降、体重下降、胸闷气短等首批症状，并记录首次、减轻、无变化、加重、新出现和消失。
- 补充说明以文字保存。患者端已接入浏览器语音识别，转写结果进入同一文本框，患者核对后提交；不支持或识别失败时可直接输入文字，后台不上传或播放每日反馈原始音频。
- 后台列表保留日期、症状变化、文字说明和来源，代录与患者提交明确区分。

### 复审结果

- 接口已验证互斥选项、同日重复提交阻止、语音转写文字保存和导出不含音频字段。
- 当前移动 Web 已验证语音入口可见、支持状态和文字降级提示；真实小程序宿主的语音识别权限与转写服务仍留到真机阶段验证。

## F07 不良反应上报、评估与跟进

### 实现结果

- 患者端按 Figma 补充设计支持症状、发生时间、患者感受和补充说明上报，保留患者原始表达。

### 复审结果与边界

## F08 同一服药时点整次确认、部分未服与更正

### 实现结果

- 首页和用药页共用同一个“日期 + 时点”记录。正常情况一次确认本时点全部药品，减少重复点击。
- 部分未服或本次未服时再展开逐药选择和情况说明；患者不能把未记录冒充为明确未服。
- 历史记录可更正，更正必填原因并保留逐药前后历史；重复提交同一结果不重复计数。
- 最近 14 个已记录时点在患者端可查，用药更正编辑时隐藏底部菜单，避免遮挡主操作。

### 复审结果

- 测试已覆盖无效时点、未来时点、整次已服、部分未服、原因必填、更正和幂等。
- 移动页实际检查了已完成、更正编辑和近期历史状态，主操作与底部安全区无重叠。

## F09 暂停、恢复、完成与退出联动

- 切换为“暂停用药”时，将未来未执行服药计划标记为已暂停；历史记录和安全随访保留。
- 从暂停恢复为“治疗中”时，只恢复由该次暂停产生的计划，不复活早已取消的其他记录。
- “已完成”取消未来服药计划；“提前退出”同时取消未来服药和未完成随访任务，并记录数量及原因。
- 上述是当前第一版本地规则；真实研究若要求退出评估或持续安全随访，上线前应按方案调整。

## F10 任务安排弹窗、提醒偏好与联系入口

- 首页任务提醒的“查看安排”已改为底部弹窗，直接展示任务类型、日期、截止时间、地点与说明，关闭后仍留在首页。
