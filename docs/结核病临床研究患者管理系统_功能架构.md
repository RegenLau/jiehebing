## 一、范围原则

- 线上只管理已在线下完成筛选并确认入组的患者。
- 医生建档并填写用药，患者通过手机号匹配档案，核对信息后完成任务。
- 通用模块维护可复用方案和内容；研究分组先建基础信息，再选择模板、设置条件及添加患者，入组后生成独立的个体方案和任务。
- 任务配置明确计时基准。默认按入组基准日，治疗相关安排可按开始用药日期；具体适用范围待研究者确认。线上启用和患者信息确认不重置这些日期。
- 第一版保留必要业务操作，减少独立菜单、重复录入、通用配置工具和复杂自动化。
- 基础 OCR 是会议明确认可的需求方向，本版将其列入 V1.0 目标。支持范围需明确；识别失败允许人工修正或补传，不承诺适配所有检查单。
- 必须由当前研究决定的盲法控制、安全通知和关键数据要求，不因分期而自动延期。

## 二、总体结构与模块关系

### 2.1 功能归属

| 模块 | 通用内容或方案 | 患者实际数据 | 研究分组负责配置 |
| --- | --- | --- | --- |
| 用药管理 | 用药方案及药品明细 | 个体方案、用药计划、打卡、发药及余药 | 关联方案，设置周期及发药、取药参数 |
| 随访任务 | 检查、复诊、取药、报告提交等任务模板 | 个人任务、提交结果及完成状态 | 选择模板，设置时间基准、起点、频次、期限及提醒 |
| 问卷管理 | 每日反馈、定期症状及不适问卷 | 患者答卷 | 关联问卷，设置执行安排 |
| 不良反应上报 | 统一上报内容与处理能力 | 患者原始上报及研究者评估、处置记录 | 确定适用要求、接收人员及提醒条件 |
| 健康科普 | 经确认的文章及用药指导 | 患者查看通用内容 | 独立模块，不在分组中配置 |

### 2.2 第一版建议菜单

功能点不等于独立菜单；同一份患者记录在全局列表和患者详情中复用。

```text
后台管理
├─ 工作台
├─ 研究管理
│  └─ 项目列表
│     ├─ 详情 → 项目基本信息与变更记录
│     └─ 分组 → 当前项目分组选择页 → 基础信息新建弹窗 / 分组详情页 → 配置页
│        ├─ 关联用药方案与执行参数
│        ├─ 关联随访问卷与执行安排
│        ├─ 关联检查等任务模板与执行安排
│        └─ 患者（本组成员）
├─ 患者管理（包含入组建档、个体方案及关联记录）
├─ 用药管理
│  ├─ 用药方案
│  └─ 用药计划（复用当前服药执行列表）
├─ 随访任务
│  ├─ 任务列表
│  └─ 任务模板
├─ 问卷管理（通用问卷、答卷查看）
├─ 检查报告
├─ 不良反应上报（原始不适、事件评估与处理）
├─ 健康科普
├─ 常用药品
└─ 账号与权限（复用管理员及个人中心等公共功能）
```

不另设完整的“研究设置”“检查管理”“取药管理”“统计中心”菜单。检查、复诊、取药执行统一进入任务列表，发药及余药在患者详情维护，统计先在工作台提供。

### 2.3 配置与执行规则

1. 通用模板可以供多个分组引用，第一版提供基础新增、编辑、查看和停用，不建设拖拽编辑器或通用条件引擎。
2. 分组只配置关联与执行条件，不在分组中再维护一套药品库、问卷库或文章库。
3. 第一版直接在分组配置，不同时建设项目默认、分组继承、多层覆盖。
4. 入组时保存所选模板及分组配置的副本，形成独立个体方案和任务安排，保留来源与版本标识。
5. 修改模板或分组默认配置不覆盖已入组患者；已有患者逐人调整并留痕，批量应用后置。
6. 模板停用后不能被新关联，已有方案和历史结果仍可查看；已引用模板不直接删除。
7. 未关联任务的健康档案上传不自动完成任务；原始报告只保存一份，由任务及“我的报告”共同引用。
8. 问卷决定“填写什么”，任务安排决定“何时填写”，答卷记录“患者实际填写了什么”。

## 三、V1.0 功能范围

以下按业务能力展开，实际菜单以第二节为准。V1.0 保留通用模板选择与分组配置的完整链路，精简的是配置深度，不是删除主流程。

### 1. 工作台

- 重点待办
  - 待审核检查报告。
  - 待跟进不适与安全事件。
  - 已逾期随访、检查及复诊任务。
  - 需联系的未打卡患者。
  - 即将取药、逾期未取药记录。
- 基础统计
  - 管理人数、治疗中人数、完成及退出人数。
  - 任务完成情况、待处理数量。
  - 点击指标进入对应筛选结果。
  - 明确区分人数、任务数、服药计划条数、报告份数和事件数。
- 第一版不新增复杂图表或独立统计中心。

### 2. 患者管理

- 患者列表
  - 查询、筛选、新增、编辑、查看详情。
  - 姓名、手机号、患者编号、研究分组、负责人员和当前状态。
  - 重复档案校验与访问范围控制。
- 已确认患者建档
  - 项目、中心、分组及入组基准日。
  - 线下入组确认信息和必要的知情同意登记信息。
  - 医生确认启用线上管理。
  - 不重复建设完整病历、候选人员筛选或线上纳排判定。
- 患者确认情况
  - 是否完成基础信息核对。
  - 是否完成药品核对。
  - 信息有误后的联系与修正记录。
  - 患者确认不改变入组基准日，不代替研究者的入组及方案确认。
- 个体用药方案
  - 按研究分组带出默认方案。
  - 医生确认，或调整药品、单次用量、频次、时间和周期。
  - 调整原因、生效时间、历史方案与修改前后内容。
  - 分组模板变更不直接覆盖既有个体方案。
  - 第一版逐人调整，不做批量同步。
- 服药记录
  - 今日、历史、逐药记录。
  - 区分已服、明确未服、未打卡。
  - 未服原因和人工联系记录。
  - 不把未打卡直接解释为未服药或连续停药。
- 发药与余药
  - 首次及后续实际发药日期、药品、数量和单位。
  - 预计剩余数量、可用天数、取药安排。
  - 患者取药完成反馈与医生发药登记分别保存。
  - 医务人员余药核对、修正原因和修正记录。
  - 第一版不做药房库存、采购、结算。
- 状态变更
  - 已确认待启用、治疗中、暂停用药、已完成、提前退出、失访。
  - 恢复用药作为操作，记录恢复时间及生效方案。
  - 变更原因、操作人、生效时间和后续任务影响。
  - 暂停用药保留必要安全监测；退出时保留研究要求的退出评估及安全随访。
- 关联记录
  - 查看任务、症状、问卷、报告、事件、发药和状态历史。
  - 第一版使用列表和标签，不建设复杂可视化时间线。

### 3. 随访任务

- 任务列表
  - 今日、待完成、已提交、需补充、已完成、已取消。
  - 逾期作为时间属性筛选，可与任务状态并存。
  - 按患者、任务类型、日期和状态筛选。
- 任务生成与调整
  - 根据分组关联的问卷、任务模板及各自时间基准生成个人任务。
  - 新增临时任务、调整日期、取消任务。
  - 保留原计划、新计划、调整原因和操作人。
  - 不建设拖拽式流程设计器。
- 每日健康反馈
  - 固定症状及减轻、无变化、加重、新出现等变化。
  - 支持无症状、首次记录和症状消失的表达。
  - 患者可语音录入，由患者端转为文字后提交；后台只接收、展示和导出补充文字，不提供每日反馈原始语音上传或播放。
  - 按日期查看历次变化，能定位首次记录改善的随访日期。
- 定期结构化随访
  - 使用研究者确认的固定题目模板。
  - 查看答卷、提交时间及重点症状或不适。
  - 与每日反馈复用表单及结果展示能力，避免同一时间重复收集相同内容。
  - 是否补充体重变化及具体采集方式，由研究者核对模板。
- 检查任务
  - 检查项目、时间窗、地点和说明。
  - 关联上传、补充和审核结果。
  - 同一次检查的上传与补充作为任务阶段，不重复计为多条待办。
  - 单独索取资料时可创建独立报告提交任务。
- 复诊任务
  - 日期、医院、科室、说明。
  - 患者完成反馈、研究者复诊结论。
  - 需要时关联方案调整或新增检查。
- 取药任务
  - 取药日期或提醒窗口、地点和联系人。
  - 患者完成反馈、实际发药记录。
  - 联系医院不自动完成取药。
- 人工追踪
  - 未完成提醒、联系时间、联系结果、后续安排。
  - 单次逾期不自动判定失访。

### 4. 检查报告

- 报告资料
  - 原图、报告类型、检查日期、患者和关联任务。
  - 任务上传与“我的报告”引用同一份资料。
  - 历次上传、补传和审核记录。
- 基础 OCR
  - 限定当前研究选定的检查类型与关键指标范围。
  - 保存原图和原始识别结果。
  - 接收患者核对及修正结果。
  - 识别失败、结果缺失时支持人工补充或重新上传。
  - 上传前给拍摄提示；不将自动图片质量判定作为首发必需能力。
- 研究者审核
  - 对照原图确认数据。
  - 核对通过、要求补充。
  - 填写补充原因，补传后再次审核，保留原资料。
  - “已核对”不等于检查结果正常。
- 关键指标
  - 保存当前研究必需的项目、检测值、单位、参考范围和确认记录。
  - 识别遗漏或错误可由医务人员修正，保留前后内容及原因。
  - 不要求第一版结构化所有检查内容。
  - 患者端异常标识的展示范围须经研究者确认；异常标识不代替风险分级或临床判断。

### 5. 不良反应上报与安全事件

- 原始不适上报
  - 症状、发生时间、患者感受、文字、语音及附件。
  - 区分临时主动上报与定期随访来源。
- 人工评估与跟进
  - 待处理、处理中、已处理。
  - 负责人员、联系记录、判断、处置结果和后续安排。
- 基础事件记录
  - 由研究者判断一般症状、AE、特别关注事件或严重事件。
  - 记录事件名称、发生及结束时间、严重程度、严重性与特别关注属性、相关性、措施和结局。
  - 严重程度不直接等于 SAE；特别关注属性和严重性可同时存在。
  - 关联原始资料、检查结果及生效用药方案。
  - 若医院使用既有完整事件报告表，可保存资料索引或附件、报告时间及后续记录，避免重复建设两套完整表单。
- 通知与处理记录
  - 至少一种实际可用且符合当前研究安排的通知渠道。
  - 通知对象、时间、发送结果、确认及处理记录。
  - 失败通知进入人工联系待办，不以静态“已提醒”标签代替实际发送。
- 第一版不建设通用医学规则引擎。
- 当前研究要求的事件报告、通知时效和安全跟踪不能因简化而省略；具体责任与执行方式在首发前确认。

### 6. 研究项目与分组管理

- 项目基本信息
  - 名称、编号、研究目的、开始及结束日期。
  - 状态：未开始、进行中、已结束；具体转换限制及对既有患者的影响待确认。
  - 新增及编辑不再维护研究类型和备注；已有模拟数据中的旧字段仅作兼容保留，不在当前页面展示或覆盖。
  - 不将研究中心、负责人、联系电话、方案版本、生效日期作为新建项目的统一必填门槛。中心归属在患者建档登记，人员与联系方式由账号和通知配置维护。
- 项目列表
  - 展示项目编号、名称、研究周期、分组数、患者数及状态。
  - 患者数按当前项目下的去重患者统计；同一患者即使同时存在项目登记与分组关联也只计一次。
  - 操作仅保留分组、编辑和状态，不提供单独的项目详情入口。
- 研究分组
  - 创建、编辑、查看分组，维护名称和说明，支持 A/B 组及多个分组。
  - 创建只填写分组名称与说明；创建后关联通用用药方案、问卷和任务模板，并添加患者。
  - 用药：设置本组默认治疗周期、首次发药数量、取药周期及提前提醒天数；实际发药以患者记录为准。
  - 随访：设置时间基准、起始偏移或指定日期、频次、完成期限及提醒。
  - 检查、复诊与发药分别设置周期，不共用一个周期字段。
  - 患者：从已建档患者中选择，同一项目内不能同时属于多个小组；归属保存不自动执行治疗初始化。
- 配置展示
  - 可查看所选模板明细及本组执行条件，避免只能看到模板名称。
  - 记录配置变更人员、时间和内容；既有患者不自动同步新配置。
- 首发条件性要求
  - 当前研究如涉及盲法，必要的信息展示和访问控制进入 V1.0，不能自动后置。
  - 当前研究如规定安全事件通知时效，V1.0 必须落实责任人、渠道、时限和执行记录。
  - 不将示例提前天数、研究周期和医学阈值写成所有项目的固定规则。

### 7. 通用方案与内容

#### 7.1 用药管理

- 用药方案库：新增、编辑、查看、停用；方案名称、说明、来源版本及药品明细。
- 药品明细：药品名称、规格、单次用量及单位、用药频次、时间、用药周期、注意事项。
- 默认发药数量、取药周期和提前取药天数可供分组带出并调整；不得当作实际发药记录。
- 个体方案落地时确定实际开始、结束日期；可复用模板使用相对周期，避免把某个患者日期写成全组固定日期。
- 用药计划复用现有服药执行列表，关联患者、项目、分组和个体方案；不与方案模板混为一张表。
- 实际余药、预计可用天数、取药日期及医生校正记录在患者详情维护，全局列表可关联查看。
- 变更记录保留时间、人员、前后内容和原因；不自动修改在组患者。

#### 7.2 问卷管理

- 统一维护每日健康反馈、每周临床症状及常见不适问卷，供分组选择。
- 第一版使用预置模板并支持基础维护：名称、说明、题目、选项及启停；基础题型为单选、多选、文本及语音补充，不做自由拖拽设计器。
- 每日固定症状及改善、无变化、加重、新出现等反馈保留；无症状、首次记录和症状消失均能表达。
- 定期症状包括咳嗽、咳痰、乏力、盗汗、发热、纳差及其他；常见不适包括恶心、呕吐、皮疹、发热等。具体题目由研究者确认，避免与当日反馈重复采集。
- 每日反馈语音由患者端先转文字再提交，属于当前流程；其他问卷/不适的原始语音与转写按各自规则，不与每日反馈混用。
- 答卷保存所用题目及选项版本；后续改题不改变历史答卷含义。
- 查看和导出答卷，区分作答人数、提交份数和题答案条数。

#### 7.3 随访任务模板

- 统一维护检查、复诊、取药、报告提交及其他任务的名称、类型、说明、提交要求和关联内容。
- 检查预置项：肝肾功能、血常规、尿常规、心电图、痰涂片抗酸染色、分枝杆菌培养、胸部 CT；首发按当前研究选用，不默认全部适用。
- 分组关联模板后设置执行时间和频次；模板自身不生成任何患者任务。
- 第一版提供简单安排表，常用每日、每周和周期检查均可配置；每两周、每两个月为可选示例，不是所有研究固定规则。
- 检查上传、补充和再次核对属于同一任务的阶段；独立索取资料可新建报告提交任务。

#### 7.4 健康科普

- 复用现有新增、编辑、详情、图片上传及上下架能力。
- 通用文章与用药指导独立维护，分组不再配置健康科普。
- 保存内容确认人员和时间，患者看到经确认的内容。
- 第一版不做 AI 问答、独立内容审批平台或自动定时推送；定时推送列入 V1.1 候选。

### 8. 公共管理与基础数据

## 六、主流程及首发完成判据

主流程：

**维护通用方案与内容 → 建项目与分组 → 分组关联模板并设置条件 → 已入组患者建档 → 个体方案与首次发药确认 → 生成任务 → 患者提交 → 研究者核对或跟进 → 调整后续安排 → 完成或退出 → 数据导出与留痕**

首发应验证：

1. 同一通用方案或问卷可被不同分组引用；选择研究分组后，正确生成独立的个体用药方案，能追溯来源。修改通用模板不覆盖既有患者和历史答卷。
2. 任务按分组配置及明确的时间基准生成，问卷内容与执行频次正确关联；患者确认信息不重置任务日期。
3. 服药、每日反馈及定期随访结果在后台和患者详情中一致。
4. 报告可以上传、识别、核对、补传、再次审核；原始资料及修改过程保留。
5. 不适可以通知、分配、跟进和记录结果，符合当前研究实际的安全处理安排。
6. 患者取药反馈与医生实际发药记录分开，发药后更新余药及提醒。
7. 方案及研究状态变更正确影响后续任务，不抹去既往记录或误停必要安全随访。
8. 必要记录可以查询、导出，并追溯关键修改。
