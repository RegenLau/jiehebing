# 结核病临床研究患者管理系统功能架构

> 更新日期：2026-09-14
>
> 文档口径：当前仓库已实现并可通过 PC 后台操作的功能
>
> 当前运行形态：Vue 管理后台 + Node.js 本地 Mock API

## 一、文档说明

本文用于描述当前后台系统的真实功能架构，不再混入早期方案、后续规划或患者端设想。

功能判断按以下优先级核对：

1. 当前后台菜单和可操作页面；
2. 页面实际调用的接口及业务校验；
3. Mock 数据模型与自动化测试；
4. README 和接口交接文档仅作为补充说明。

本文中的“已实现”是指当前本地演示环境已经具备相应页面、交互和 Mock 数据闭环，不代表已接入生产数据库、真实 OCR、微信服务或消息服务。

## 二、当前交付范围

### 2.1 已纳入当前交付

- PC 端后台管理系统；
- Node.js 本地 Mock API；
- 研究项目、研究分组和组内执行配置；
- 患者建档、入组、治疗、发药、库存和状态管理；
- 用药方案、患者用药计划和执行登记；
- 随访任务、每日反馈、问卷、检查报告和不良反应跟进；
- 健康科普、常用药品、管理员账号；
- 工作台统计、筛选联动和业务数据导出。

### 2.2 当前运行边界

- 当前业务数据由 Node.js Mock 服务保存在内存中，重启服务后恢复为初始数据；
- `backend/` 中的 PHP 工程不是当前后台页面的数据来源；
- 当前不包含患者端页面、患者登录、微信授权或患者自主填报入口；
- 当前上传、识别、提醒和发送等外部能力均为本地演示逻辑，不等同于生产服务。

## 三、当前功能总览

### 3.1 业务主链路

```text
研究项目
  └─ 研究分组与组内配置
       ├─ 用药方案
       ├─ 问卷安排
       ├─ 检查/提醒安排
       └─ 领药提醒
            ↓
患者建档并入组
  ├─ 固化入组时的分组配置快照
  ├─ 创建患者治疗版本
  └─ 完成首次发药
            ↓
患者执行与随访
  ├─ 用药计划与服药登记
  ├─ 当前待办与每日反馈
  ├─ 问卷答卷查看
  ├─ 检查报告上传与审核
  └─ 不良反应处理跟进
            ↓
工作台统计、明细下钻与数据导出
```

## 四、功能架构明细

### 4.1 工作台

工作台名称为“随访工作台”，用于查看研究执行概况和需要优先处理的事项。

已实现功能：

- 统计范围：今日、近 7 天、近 30 天，并可选择统计日期；
- 范围筛选：研究项目、研究分组；
- 核心指标：患者总数、在组患者占比、应执行用药计划数、用药完成率、新增不良反应数；
- 趋势图表：患者与用药执行趋势、研究状态分布、不良反应严重程度分布；
- 待办入口：逾期用药任务、待跟进不良反应、待审核检查报告；
- 指标和待办可下钻到对应业务列表，并携带当前日期、项目和分组条件。

工作台统计与明细列表使用一致的筛选口径，避免指标与下钻结果不一致。

### 4.2 研究管理

#### 4.2.1 项目列表

已实现功能：

- 按项目编码或项目名称搜索；
- 查看项目编码、名称、研究周期、分组数量、患者数量和状态；
- 新建、编辑项目基础资料；
- 项目字段包括项目编码、项目名称、开始日期、结束日期和研究目的；
- 进入项目分组列表；
- 手动结束项目；
- 删除尚未建立分组且未纳入患者的空项目。

项目状态结合研究周期和手动结束状态计算。项目结束后，项目、分组及组内配置转为只读，历史数据继续保留。

#### 4.2.2 研究分组

已实现功能：

- 查看项目下的分组列表；
- 新建、编辑分组名称和说明；
- 查看分组患者数量；
- 进入分组配置；
- 删除尚未纳入患者的空分组。

当前分组患者列表仅用于查看和进入患者详情。患者所属研究和分组由患者建档入组流程确定，不在分组页面直接增删成员。

#### 4.2.3 分组配置

分组配置包含以下页签：

- 患者列表：查看已入组患者；
- 用药方案：选择已启用的通用方案，或配置当前分组专用方案；
- 随访问卷：配置需要执行的问卷及执行时间；
- 领药提醒：配置提前提醒天数、提醒时间和领药要求；
- 其他任务：配置检查或普通提醒任务。

问卷和任务安排支持：

- 计算基准：入组日期、治疗开始日期、指定日期；
- 首次执行偏移天数；
- 重复间隔天数；
- 完成期限天数；
- 提醒时间；
- 预览后续执行日期。

指定日期类型为一次性安排，不再叠加偏移或重复间隔。领药提醒是分组配置中的独立规则，不作为普通任务模板处理。

### 4.3 患者管理

#### 4.3.1 患者列表

已实现功能：

- 按患者姓名、手机号或患者编码搜索；
- 按患者状态、项目、分组和入组日期筛选；
- 查看患者编码、联系方式、所属研究和分组、当前用药方案、患者状态、计划确认状态及入组日期；
- 进入患者管理流程；
- 进入患者详情；
- 按当前筛选条件导出患者数据。

患者编码是系统内稳定的业务标识，支持查询、详情定位和导出关联。

#### 4.3.2 患者建档与入组

新患者建档采用三步流程：

1. 基本信息：姓名、手机号、性别、出生日期；
2. 研究信息：项目、分组、责任人、入组日期，并确认已线下完成入排条件核验和知情同意；
3. 用药与首次发药：确认入组用药方案并登记首批发药数量。

建档入组的当前规则：

- 只能选择待开始或进行中的项目；
- 所选分组必须已配置可用的用药方案；
- 入组时固化分组配置快照，后续修改分组配置不会直接覆盖已入组患者；
- 患者、治疗版本和首次发药一次性创建，任一步骤失败则不产生部分数据；
- 首次发药为必填步骤；
- 使用客户端请求标识避免重复提交产生重复患者或重复发药记录。

#### 4.3.3 已入组患者管理

已实现功能：

- 修改患者基础信息，并填写修改原因；
- 查看当前生效和待生效的治疗版本；
- 查看历史治疗方案；
- 选择分组方案或建立患者个体调整方案；
- 调整患者药品启停、单次剂量、每日次数和提醒时间；
- 设置新治疗版本的生效日期；
- 在明确选择时调整疗程结束日期；
- 登记后续发药；
- 对错误发药记录执行更正或作废；
- 查看预计剩余库存、预计缺药日期和领药提醒；
- 登记患者实际日末库存并填写原因；
- 变更患者业务状态；
- 查看患者管理操作记录。

新治疗方案通过版本方式生效，不覆盖已执行事实。未来生效的方案保持待生效状态；已执行的用药计划、发药记录和历史治疗版本继续保留。

发药更正会保留原记录并生成替代记录；发药作废会保留原始记录和作废原因，满足业务追溯要求。

#### 4.3.4 患者状态

当前患者状态包括：

- 待启用；
- 治疗中；
- 暂停用药；
- 已完成；
- 提前退出；
- 失访。

系统会根据当前治疗版本自动判断待启用、治疗中和已完成。人工状态变更仅允许当天生效，并按合法路径执行：

- 待启用可变更为提前退出或失访；
- 治疗中可变更为暂停用药、提前退出或失访；
- 暂停用药可恢复为治疗中，也可变更为提前退出或失访。

暂停用药时，未来未执行的用药计划暂停，但问卷和安全随访继续保留；恢复治疗时，只恢复当前或待生效治疗方案范围内的计划。提前退出或失访后，普通任务停止，标记为安全随访的任务继续保留。

#### 4.3.5 患者详情

患者详情当前包含：

- 今日用药计划；
- 全部用药计划，可按日期筛选；
- 患者当前药品和用药指导；
- 问卷执行轮次及对应答卷；
- 不良反应记录；
- 每日反馈记录；
- 检查报告记录。

患者详情用于聚合查看现有记录，不提供患者端填报入口。

### 4.4 用药管理

#### 4.4.1 用药方案

已实现功能：

- 按方案名称和启停状态筛选；
- 查看方案版本、药品数量、疗程天数和更新时间；
- 新建、编辑和预览通用用药方案；
- 启用或停用方案，并记录原因；
- 查看方案版本历史；
- 通过常用药品搜索添加药品；
- 在通用方案页面上传处方图片，由本地 Mock 生成识别结果后辅助添加药品。

单个药品可配置：

- 发药数量；
- 单次剂量和剂量单位；
- 每日服药次数；
- 各次提醒时间；
- 服药时机；
- 用药天数。

领药周期根据发药数量和计划用量自动计算，不由用户直接填写。方案更新形成新版本，不自动覆盖已使用该方案的分组和患者。

#### 4.4.2 用药计划

已实现功能：

- 查看今日计划或全部计划；
- 按患者编码/姓名、执行日期、执行状态、项目和分组筛选；
- 支持逾期计划快速筛选；
- 登记“已服”“未服”或“联系”处理结果；
- 每次人工登记均要求填写说明；
- 按当前筛选条件导出用药计划。

当前计划状态覆盖已确认服药、未确认服药、明确未服、暂停和取消等业务结果。

### 4.5 随访任务

#### 4.5.1 当前待办

任务列表定位为“患者当前待办”，主要展示待处理和需要补充资料的任务。

已实现功能：

- 按患者、任务名称、任务类型、状态、是否逾期、项目、分组和日期筛选；
- 查看普通提醒、检查、问卷和健康反馈类待办；
- 查看任务来源、计划日期、截止日期、提醒时间、要求和关联患者；
- 从任务详情跳转到患者详情；
- 跳转到关联检查报告；
- 跳转到问卷指定轮次的答卷；
- 新建一次性普通提醒或检查任务；
- 按当前筛选条件导出任务。

当前待办由分组任务安排、问卷安排、每日反馈规则、领药提醒和一次性临时任务共同产生。任务列表本身不提供患者端提交能力。

#### 4.5.2 每日反馈

已实现功能：

- 按患者、反馈日期、项目、分组和日期范围筛选；
- 后台代患者登记当日无不适，或选择症状并填写变化说明；
- 记录信息来源、操作人和操作时间；
- 按当前筛选条件导出反馈记录。

当前未接入患者语音或音频文件采集、存储和播放。

#### 4.5.3 任务模板

已实现功能：

- 管理普通提醒和检查两类模板；
- 配置模板名称和执行要求；
- 查看、编辑、启用或停用模板；
- 查看模板版本历史。

检查模板可用于后续报告流程。领药提醒由分组单独配置，不属于任务模板。

### 4.6 检查报告

#### 4.6.1 报告列表与上传

已实现功能：

- 按患者、报告状态、项目、分组和报告日期筛选；
- 后台新建患者检查报告；
- 选择关联患者和可匹配的检查任务；
- 填写报告类型、报告日期和备注；
- 上传图片或 PDF；
- 按当前筛选条件导出报告数据；
- 进入报告详情。

当前上传支持 JPG、PNG、GIF 和 PDF，单个文件最大 10 MB。上传后由本地 Mock 生成模拟 OCR 结果，仅用于演示审核流程。

#### 4.6.2 报告审核

报告详情已实现：

- 查看原始上传文件和补传版本；
- 预览图片和 PDF；
- 查看 Mock OCR 原始结果；
- 人工修订报告类型、报告日期、文字结论和指标明细；
- 增删指标，并维护指标值、单位、参考范围和异常标记；
- 审核通过；
- 退回补充，并填写明确的补充要求；
- 上传补充资料后重新进入待审核状态；
- 保留 OCR 原始数据和人工审核后的结构化数据。

报告状态包括待审核、需补充和已审核。报告只更新与其明确关联的检查任务，不会误完成同一患者的其他任务。

### 4.7 不良反应上报

已实现功能：

- 按患者姓名/编码、严重程度、处理状态、负责人、项目和分组筛选；
- 查看患者、发生时间、症状、严重程度、处理状态、负责人、联系方式和上报时间；
- 导出不良反应数据；
- 查看上报原始信息；
- 登记处理状态、负责人、联系渠道、联系结果和下一步行动；
- 查看按时间排列的处理记录；
- 通过数据版本校验避免多人同时保存时覆盖他人结果。

当前后台页面聚焦“上报查看 + 处理跟进”，未提供完整的 AE/SAE 医学评估表、因果关系判定、转归结论或伦理上报流程。

### 4.8 问卷管理

已实现功能：

- 按问卷标题、问卷编码和状态筛选；
- 查看题目数量、答卷数量、参与患者数量和状态；
- 新建问卷基础信息，系统自动生成问卷编码；
- 编辑问卷标题、说明和题目；
- 支持单选、多选和文本题；
- 配置必填、选项、互斥选项、条件补充文本和输入提示；
- 启用或停用问卷；
- 查看问卷详情；
- 按项目、分组和提交时间导出答卷，一份答卷占一行。

问卷执行按患者任务轮次保存，使用任务标识和答卷标识定位具体一轮答卷。患者详情可查看每轮计划时间、截止时间、状态、提交时间和具体答案。

已产生历史答卷的题目结构受保护，避免后续编辑破坏已提交数据。当前后台不提供患者填写问卷的页面。

### 4.9 健康科普

已实现功能：

- 按标题或摘要搜索文章；
- 按发布状态筛选；
- 新建、编辑和查看文章；
- 维护封面地址、摘要、发布时间、排序和正文内容；
- 记录内容确认人和确认时间；
- 上架或下架文章。

当前仅完成后台内容管理，未包含患者端展示和消息推送。

### 4.10 常用药品

已实现功能：

- 按药品名称、生产企业或医保编码搜索；
- 按启停状态筛选；
- 查看标准药品资料；
- 查看和维护用药指导；
- 启用或停用药品。

当前页面用于维护方案配置所需的常用药品资料和指导，不是药品采购、库存或结算系统。

### 4.11 管理员

已实现功能：

- 查看和搜索管理员账号；
- 新增、编辑管理员；
- 维护用户名、姓名、所属医院、科室、手机号、邮箱和状态；
- 设置或修改密码；
- 启用或停用账号；
- 使用个人中心维护当前账号资料。

管理员停用或密码修改后，已有登录会话会失效。当前未形成按研究项目、分组或盲态控制的细粒度权限体系。

## 五、核心业务规则

### 5.1 分组配置快照

患者入组时复制并固化当时的分组用药、任务、问卷和提醒配置。分组后续调整只影响之后入组的患者，不直接改变既有患者的执行安排。

### 5.2 治疗方案版本

患者用药调整通过新建治疗版本完成。系统保留旧版本及其执行记录；新版本可立即生效或在未来日期生效。疗程结束日期只有在操作人明确调整时才改变。

### 5.3 患者建档与首次发药原子性

患者信息、研究入组、治疗版本和首次发药作为一个完整业务动作处理。任何关键校验失败时，不保留不完整的中间结果；重复提交通过客户端请求标识进行幂等控制。

### 5.4 发药和库存追溯

有效发药记录是预计库存计算的主要输入。登记实际库存后，系统以最近一次实盘结果作为新的计算起点。更正和作废不删除原记录，保留原因和替代关系。

### 5.5 状态与任务联动

患者暂停、恢复、完成、退出或失访会影响后续普通用药计划和随访任务，但已发生事实不被删除。问卷和安全随访按其业务属性继续保留。

### 5.6 问卷轮次与报告关联

问卷答卷必须关联到具体任务轮次，不能仅按患者和问卷笼统匹配。检查报告只联动其明确选择的检查任务，避免跨轮次或跨任务误更新。

### 5.7 统计、列表和导出口径

工作台下钻、业务列表和导出使用相同的项目、分组、日期及状态条件。导出覆盖符合筛选条件的完整数据，不仅导出当前分页。

## 六、主要业务数据关系

| 业务对象 | 关键关系与用途 |
| --- | --- |
| 研究项目 | 包含多个研究分组，是统计和筛选的最高业务范围 |
| 研究分组 | 归属项目，保存用药、问卷、任务和领药提醒配置 |
| 分组配置版本 | 保存配置修订信息，为患者入组快照提供来源 |
| 患者 | 归属一个项目和分组，使用稳定患者编码贯穿各业务记录 |
| 患者入组快照 | 固化患者入组时的分组配置，隔离后续分组修改 |
| 治疗版本 | 描述患者某一时间段内的用药方案和疗程 |
| 发药记录 | 记录实际发放数量，支持更正、作废和库存估算 |
| 用药计划 | 由患者治疗版本生成，记录每次计划和执行结果 |
| 随访任务 | 来源于分组安排、问卷、每日反馈、领药提醒或临时创建 |
| 问卷答卷 | 关联患者、问卷、具体任务轮次和唯一答卷标识 |
| 检查报告 | 关联患者及可选检查任务，保存原文件、OCR 和审核数据 |
| 不良反应 | 关联患者，保存原始上报和后台处理跟进记录 |
| 每日反馈 | 关联患者和反馈日期，保存症状、变化、来源和操作信息 |

## 七、数据导出

当前支持生成 XLSX 文件的业务模块包括：

- 患者列表；
- 用药计划；
- 当前随访任务；
- 每日反馈；
- 检查报告；
- 不良反应；
- 问卷答卷。

导出文件按当前查询条件生成，并包含符合条件的全部记录。
