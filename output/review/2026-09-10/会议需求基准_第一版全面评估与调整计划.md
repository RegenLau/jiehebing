## 3. 建议的最短业务流程

### 3.1 医生准备研究

1. **创建研究主题**：名称、编号、说明；研究周期用于管理，不替代个人用药周期。
2. **创建小组**：名称、说明即可；之后进入组内配置。主题/组可先建，资源可以提前准备，也可配置时创建后返回，避免流程被空资源库卡住。
3. **关联可复用资源**：选一个默认用药方案、需要的问卷和任务、一个提醒方案；默认使用资源已有值。
4. **核对本组安排摘要**：例如“入组后第7天开始，每14天一次问卷；检查需上传报告；用药按已选方案执行”。示例时间仅演示配置表达，不是临床默认。

配置无需审批流。未配齐显示“待完善：用药方案/随访安排”，不能出现一个“保存成功”就让医生误以为患者已经有全部可执行任务。

### 3.2 医生添加患者：一次连续操作

建议使用一个页面内的三个步骤，保留已填内容：

| 步骤 | 医生做什么 | 系统自动做什么 | 保存后的结果 |
|---|---|---|---|
| 1 基本信息 | 录入姓名/研究编号、手机号、研究必需的基础信息 | 检查重复手机号；负责人默认当前人员或已配置团队 | 患者档案与手机号准入关联 |
| 2 研究分组 | 选择研究、小组、入组日期 | 带入该组方案、问卷、任务、提醒；从组内发起时预选 | 明确患者归属与各类安排来源 |
| 3 用药与安排核对 | 核对药品、规格、用法用量、开始日期；需要时个体调整；若已发药填写实际数量和日期 | 预览下一次用药、首批随访日期和预计余药；按规则保存个人快照 | 患者可以登录查看并确认个人安排 |

主动作建议为“保存患者与安排”，不让医生先保存档案，再找方案确认、再找发药、再找启用、再代勾患者确认。分步填写是为了理解，最后不必变成多次无提示提交。

确有资料不全场景时可“暂存待完善”。已登记患者可以看到待配置说明，但未核定方案不能显示为可打卡安排。研究入组日期、线上建档日期、用药开始日期分别保存，患者稍晚登录不改变临床时间安排。

### 3.3 患者首次进入

微信身份与可信手机号匹配后台档案 → 核对基本信息 → 核对个人用药方案 → 首页。

- 未匹配：说明“暂未查询到档案，请联系研究人员”，提供已配置联系方式；不引导自行注册研究患者。
- 信息正确：一次确认进入下一步。信息有误：指出错误并提交更正请求，不让患者修改研究分组或自己重写处方。
- 用药确认同时区分“拿到的药和数量”与“医生安排如何服用”；“核对无误”不等于“本次已经服药”。
- 确认结果记录本人/代录来源、时间和方案版本。医生更改用药后只要求核对变更内容，不重复核对没变的姓名等信息。
- 有疑问时保留联系及报告/反馈入口，明确待医生核对；系统不自行给出停药、补服或剂量调整建议。

### 3.4 日常与医生跟进

1. 患者打开首页，看到当前待记录或下一次服药及最近的待办。
2. 正常服药按时点一键记录；部分未服时才展开药品及原因。
3. 到达随访时间完成结构化表单；平时有变化可主动反馈，语音仅作为输入方式。
4. 检查任务打开后看到具体安排，上传报告 → OCR → 患者核对 → 提交；“我的报告”同步可查。
5. 医生在工作台集中看到需处理反馈、待核对报告、逾期任务；点击进入同一患者上下文处理。
6. 医生登记实际领药/修正数量，系统更新预计余药及取药提醒。
7. 按研究/组导出本次采集记录，保留时间、来源、轮次和关键修改历史。

## 4. 模块边界：保留能力，减少重复配置

### 4.1 建议导航

| 一级入口 | 包含内容 | 简化的原因 |
|---|---|---|
| 工作台 | 三类待办、少量人数及完成摘要 | 医生日常先处理事项，再看图表 |
| 研究管理 | 研究主题 → 小组 | 保留本轮要求的层次 |
| 患者管理 | 患者列表、统一患者详情 | 查看、修改、记录放在同一患者上下文 |
| 随访管理 | 任务、检查报告、情况反馈；服药执行记录可作为同区子页或患者用药视图 | 集中跨患者的执行与跟进 |
| 方案与模板 | 用药方案、随访问卷、检查/复诊/取药任务、提醒方案 | 各模块仍独立维护，但不各占一个一级菜单 |
| 基础设置 | 常用药品、健康教育、账号与个人资料 | 降低日常导航密度，复用既有基础能力 |

这是导航分组建议，不要求删除现有功能或立即迁移数据。若用户更熟悉现菜单，可以先保持一级导航，只合并患者详情和重复配置，再做导航收敛。

### 4.2 小组页建议采用四个明确页签

**患者｜用药方案｜随访安排｜提醒设置**。

- 患者：名单及查看；“新增患者”打开统一建档并带入当前研究和组，不另建一套组内患者编辑。
- 用药方案：选择模块方案，显示简明药品表；默认参数收为摘要，“调整本组默认值”时才展开。
- 随访安排：问卷、检查、复诊、取药统一列出类型、内容、执行时间和完成要求。问卷仍从问卷库选择。
- 提醒设置：选择提醒方案；明确服药、任务开始/临近截止、逾期、余药不足等适用场景。只显示这个小组实际启用的场景。

将当前“随访任务-问卷 / 随访任务-提醒”改为以上职责，能避免把“复查这件事”和“通知患者去复查”混为一谈。配置入口进入对应配置页签，不默认落到只读患者名单。

### 4.3 三层数据归属

| 层级 | 负责什么 | 不应该发生什么 |
|---|---|---|
| 模板资源 | 可复用药品用法、题目、任务要求、提醒默认规则 | 模板直接等同某患者实际服药/领药 |
| 小组安排 | 选择资源及研究特定时间安排 | 在组内复制维护另一份药品库和问卷编辑器 |
| 患者个人安排 | 入组时采用的内容、个体调整、生效日期、实际领药和执行事实 | 修改模板自动改写患者历史；同组某个人调整影响全组 |

后台可以保留必要快照和修改记录，普通用户不必在每张表维护“第几版”。模板更新后，小组显示“来源已更新，可查看差异”；是否采用由医生明确操作。对已有患者不自动覆盖，对后续新入组患者使用本组当时生效配置。

### 4.4 任务与问卷采用一条执行链

问卷回答“填什么”，小组安排回答“什么时候填”，患者任务回答“这次该谁填”，提交记录回答“这次填了什么”。

同一问卷用于第1次和第2次随访时，必须有两个任务和两份答案。第一版不需要复杂问卷引擎，但不能继续用“患者+模板只能答一次”的旧模式。模板修改不改写已提交内容。

周期界面使用自然语言，例如“入组当天 / 入组后第N天”“单次 / 每N天重复”“开放后N天内完成”。显示下一两个预计执行日期，避免要求医生理解“0为单次、起始偏移”等技术表达。确需按月执行时必须明确按日历月还是每30天，不自行等同。

### 5.1 状态不必多，但联动不能省

| 场景 | 建议规则 |
|---|---|
| 已建档但方案未核定 | 可以识别患者身份，显示“医生正在完善安排”；不生成可确认已服的空方案 |
| 患者首次核对 | 记录已核对内容和时间；未核对与医生未配置是不同状态 |
| 医生调整用药 | 从明确生效时间更新未来计划；保留已发生记录；防止当日旧新方案重复生成 |
| 暂停用药 | 暂停相应未来服药计划/提醒；原有症状随访、检查任务按研究安排继续，不能一律取消 |
| 恢复用药 | 按医生确认的恢复日期和当前方案恢复/生成未来计划，不回补暂停期间为漏服 |
| 治疗结束 | 停止相应服药计划，但研究随访可能继续；不能等同退出研究 |
| 退出研究 | 明确取消常规后续研究任务及提醒；保留历史；如研究要求继续必要跟进，应有明确安排，不能自行推断 |
| 长期未联系 | 首版可作为待跟进标记，不自动认定退出、不自动改用药 |
| 错误打卡或代录 | 保留更正原因和来源；未打卡、患者明确未服、医生代录已服分别可识别 |

### 5.2 提醒与余药的首版边界

“提醒方案”建议实现成轻量可复用资源，不建设短信、电话、多通道升级平台。会议明确提醒需求，但没有选定短信或电话；旧服务有微信订阅消息代码，只能作为可复用候选，实际可用性仍需联调。

患者“提醒设置”只能管理允许的通知偏好/授权，不能悄悄改变医生的处方时刻、剂量或研究任务截止日。通知失败或未授权时，首页/任务仍需展示同一项待办。发送成功不等于患者已读、已服药或已完成任务。

实际发药应有数量和计量单位。若按盒登记、按片服用，必须有已确认的包装换算。药品预计剩余天数取各药独立计算结果，整体提醒以先不足的药为依据；补药后更新同一患者用药记录。第一版支持当前研究需要的频次即可，但现代码按“每日N次”生成的限制必须与真实方案核对，不能事后才发现研究包含非每日安排。

### 6.2 建议采用的共同排版规则

- 页面标题、说明、主按钮、筛选栏、内容区按同一顺序；同级标题使用一致字号和外边距。
- 列表只保留直接帮助识别人、判断状态和执行下一步的列。数字编号不强制折行，长名称提供可读摘要和查看完整内容。
- 只读数据不使用整排禁用输入框；编辑时再切换表单，减少“我能不能改”的疑惑。
- 长页和长弹窗确保保存/取消始终容易到达；不要让用户滚到数页后才能确认完成。
- 表单区分必填、选填和后续补充；同类日期、下拉、数字输入宽度一致，不因控件默认样式忽宽忽窄。
- 状态必须有文字，不能仅靠浅绿/浅黄/浅灰区分。现截图存在浅色文字可读性风险，本轮未测量对比度数值，也未做完整键盘/读屏验收。
- 后续在常用笔记本视口与较小窗口复核主要流程，重点看横向滚动、固定操作列、弹窗高度、200%缩放及键盘焦点，不以截图无错位代替可访问性合规结论。

### 7.2 特别需要统一的五件事

1. **确认用药方案与确认已服药不是同一动作。** 首次核对是确认安排与实物信息；日常打卡记录已经发生的服药事实。
2. **首页和用药页共用一条记录。** 首页显示4种药、用药页示例显示3种；07:30与07:00也不一致。当前只能判定原型样例未统一，不能直接推断实际运行算法有错。
3. **必填随访与日常记录不同。** 会议经过讨论保留定期症状问卷，同时认可自由小结。建议默认定期按组要求完成、日常自愿；若医方确实要求每日采集，再在小组设置，不让患者重复答两份同内容表单。
4. **已上传、患者已核对、医务人员已核对、检查正常是不同含义。** 界面只显示对当前用户有用的下一步，但底层不能合为一个完成字段；“已核对”不等于结果正常。
5. **取药提醒必须能更新。** 联系医院不是自动记为已取药；医生登记实际发药后更新余药。预计药量不足与约定取药日期分别表达。

### 7.3 视觉细节优先级

- P1：任务一级页补齐底栏；首次确认完整显示用药内容与错误分支；主按钮文案具体；状态下有下一步。
- P1：药品名称、单次用量、单位、时刻优先于厂家、装饰图和包装图片；避免关键数值用很浅的灰色。
- P1：症状变化的选择区域目前较密，建议整块可点、文字可读；“无不适”不与其他症状同时成立。触控面积应在真机核对，本轮未测实际热区。
- P1：上传、识别、提交都有进度与失败恢复；内容不应被底部按钮或安全区挡住。
- P2：压缩医生装饰插画占用，给长药名或待办留空间；没有任务时不强行填满页面。
- P2：统一一套研究者确认的演示患者、药品和时间线。当前用药确认页与服药页采用不同药品样例，不宜直接用于整条流程演示。

### 8.3 端到端验收清单

1. 未登记手机号无法进入研究业务；登记后匹配同一患者；重复登录不产生重复患者。
2. 新建研究A/B两个组，分别关联不同方案和问卷；患者只收到其所属组安排。
3. 一位患者个体调整后，另一位同组患者、组模板和已发生记录保持原状。
4. 确认页完整展示药品规格、数量、单次量、单位、频次/时刻、服法和起止；患者发现错误可反馈，不被迫点正确。
5. 患者稍晚登录，入组/治疗基准不重置；未确认或未配置时提示正确。
6. 首页与用药页记录同一时点；重复点击不重复；部分未服不被记为整次全部完成。
7. 未记录和明确未服分开统计；医生代录显示来源及原因；更正留痕。
8. 同一问卷在两轮随访各提交一次，答案互不覆盖；原题变更不影响已提交显示。
9. 周期任务按已选基准计算，提前/到期/逾期显示一致；未选择的模块不生成患者任务。
10. 日常自由记录不被误算为未完成强制任务；研究要求的周期反馈仍按时出现。
11. 症状改善、加重、首次、消失和无症状均有明确记录，缺失答案不等于正常。
12. 语音拒绝授权或转写失败时可文字完成；转写结果由患者确认再提交。
13. 检查任务上传报告后“我的报告”看到同一份；独立上传不会误完成其他任务。
14. OCR成功、部分识别、失败均可完成核对流程；患者改值、原识别值和原图可追溯。
15. 需补充回到原报告并保留前次资料；已核对不显示成“检查正常”。
16. 发药登记单位可计算；未打卡按既定估算规则处理；明确未服、暂停、补发、盘点能合理更新余药。
17. 暂停无服药提醒；恢复正确生成后续计划；治疗结束仍保留应做研究随访；退出按约定处理未来事项。
18. 相同场景反复调度不重复通知；通知失败/未授权仍可在任务看到待办；消息跳到正确患者自己的任务。
19. 主动反馈和定期反馈中的同一问题不重复变成两张独立处理单；医生联系结果可回看。
20. 健康教育只展示已确认内容；个人用法优先，不与通用药品说明混淆。
21. 所有导出按研究/组/日期应用筛选，含任务轮次和来源；表格行数不是接口页数或题答案数冒充人数。
22. 正式环境仅允许患者访问自身数据；医生权限符合试点职责；测试入口不作为生产准入方式。
23. 常用视口下患者列表状态/操作可见，长弹窗能完成，手机长页面可滚动且不挡底栏。
24. 网络失败、重复提交、返回再进入、服务重启分别验证；已保存数据与完成状态可恢复。
